This is a working manual-practice app, not a live AI examiner. No sample score is presented as a real AI result.

Working in this public app

  • English student onboarding and Bee avatar.
  • Real browser-side text extraction from PDF, TXT and Markdown.
  • Notes, marking criteria and custom questions.
  • Timed oral practice with pause, question replay and typed answers.
  • Browser dictation when supported; optional local audio recording.
  • Persistent session history, saved answers, audio playback and downloads.
  • Shared-device examiner scores and feedback, explicitly labelled.
  • Weak-question drills: examiner scores below 65, or student-selected questions.
  • JSON export of text/results, and local session deletion.

Partial or dependent on your browser

  • Dictation depends on browser support and microphone permission. It may use your browser vendor’s speech service.
  • Recordings are local to the current browser. Synthetic-microphone recording was tested; judges should test their own hardware.
  • PDFs need a text layer. There is no OCR or Word/PowerPoint import.
  • Persistence is real browser persistence, not cloud storage. Normal reloads retain data. Private-browser data disappears when the private session is closed.

Not connected / not claimed

  • No AI question generation or automatic grading in this public deployment.
  • The separate Node source implements an AI-provider adapter tested with a mock provider, not a paid live model.
  • No multi-user accounts, cloud sync, remote live classrooms or institutional-grade assessment.
  • No accent, pronunciation or spoken-fluency scoring.
  • No claim that user interviews, learning improvements or score gains have been validated.

Sample data, clearly separated

“Try sample notes” loads authored study notes and two questions as setup inputs. It does not create completed sessions, answers or scores. Answers are entered live. Examiner marks are entered by the person demonstrating the app.

Architecture today

Static assets are delivered over HTTPS. Each browser has its own localStorage for sessions and answers and IndexedDB for audio. Visitors cannot see each other’s records through the app. This is device isolation, not authenticated user separation: anyone sharing the same browser profile can see its records.

Example model: Session {id, course, material, rubric, questions[], answers[], elapsed, feedback}; Answer {text, reflection, needsWork}; Audio {sessionId:questionIndex → Blob}. There is no central user table or database in the public demo.

What would break first at scale?

Static delivery can serve independent visitors without a central write bottleneck, but browser quota and device loss limit persistence. A production service needs authenticated user IDs, server-side ownership checks, a database for sessions, object storage for audio, upload limits, asynchronous processing, AI usage quotas and evaluation monitoring. These are proposed next steps, not implemented features.

Problem evidence

Monash University recommends practising oral answers and recording yourself to check clarity and pace. Melbourne describes interactive oral assessment as unscripted dialogue and recommends practice sessions and feedback. These support the practice workflow; they do not prove Bee’s effectiveness or demand specifically among all international students.
